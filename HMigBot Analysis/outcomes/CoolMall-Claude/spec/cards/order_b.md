## Cross-cutting notes
The confirm page VM reads and deletes the MMKV caches in init, so the page cannot rebuild data after process recreation (the item list goes empty); prices are computed only on the client for display, while the server computes the final price from couponId; the payment amount comes from the route param price (Int, in yuan; shown as `.00`), with nothing on the payment page re-querying the order. Pay entry points: the confirm page (from=confirm, closes confirm via navigateAndCloseCurrent) and order detail (OrderDetailViewModel.kt:288, no from). Refund/comment entry points: order detail/order list; both return via popBackStackWithResult so the previous page refreshes. Confirm enables the minimum loading duration enableMinLoadingTime=true. **Does not exist in source**: payment countdown, WeChat/QQ actually paying, a simulated payment button (WeChat/QQ are display-only).

## Platform risks
- Alipay: Android uses PayTask.payV2 (blocking, off main thread); HarmonyOS needs the Alipay HarmonyOS SDK (@cashier_alipay/cashiersdk) or a fallback path; if unavailable, it must be clearly degraded and the result-code mapping (9000/6001/other) and the post-payment navigation still kept. A real payment is on_device only.
- Image picking/upload: Android PickVisualMedia+Uri → HarmonyOS PhotoViewPicker (photoAccessHelper); Tencent COS direct upload needs to read the file via fd/sandbox copy and do the signing in ArkTS (reimplement FileUploadServiceImpl signing logic).
- Address selection result passed back (SelectAddressResultKey) and RefreshResult passed back need an equivalent in Navigation/NavPathStack (onPop/result callback).
- System back interception on the payment page (BackHandler) → onBackPressed/NavDestination.onBackPressed.
- MMKV cross-page handoff: HarmonyOS can use MMKV-ohos or preferences; keep the "delete after reading" semantics.
- Number formatting: PriceText takes .toInt() for display (truncating decimals); the coupon amount is Double; ArkTS should keep the same truncation display to avoid mismatches.
