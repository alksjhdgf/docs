## Cross-cutting notes
The list page has 7 independent state sets (uiState/list/refreshing/loadMore/pageIndex/loaded flag), driven by `selectedTabIndex` + `isAnimatingTabChange`. A tab tap sets the animating flag → pager animateScrollToPage → clears it when the scroll ends; during the animation, page changes caused by swiping are ignored, so intermediate pages are not loaded by mistake. The first entry to the initial tab enforces a minimum 320ms skeleton; detail/logistics use BaseNetWorkViewModel enableMinLoadingTime (320ms). Load-more success first sets LoadMoreState.Success, waits 400ms, then appends the data. Refresh sets the current tab's flag to reload immediately; other tabs reload lazily on their next selection. The cancellation reasons load only once after the sheet is fully expanded (to avoid jank during the animation), and are cached after success. Error toasts: cancel/confirm-receipt/logistics requests show error toasts by default (ResultHandler showToast=true); list paging and the dictionary request do not (showToast=false).

## Platform risks
- The HarmonyOS side needs Tabs(barMode Scrollable)+Swiper/TabContent linkage with a guard against intermediate pages loading during the animation; each page keeps its own paging state and loads lazily, and a refresh-all must reset the 7 loaded flags.
- The cross-page "pass back a refresh flag on return" relies on a Navigation3 result channel; ArkTS needs NavPathStack.pop(result)/onPop or an event bus to be equivalent, and detail must also intercept the system back (onBackPressed/NavDestination.onBackPressed) to carry the result.
- The detail page uses `data.address!!`: an order with a null address crashes on Android; ArkTS should handle null safely (deviation to record). The logistics page `courierPhone.toString()` shows the literal "null" when null.
- `复制` / `拨打` are empty implementations in the source; the migration should faithfully keep them as no-ops or record any enhancement explicitly (pasteboard/call require system capabilities).
- The cancellation-reason sheet loads after it is "fully expanded", so the HarmonyOS bindSheet needs an equivalent onAppear/height-change callback; DictSelectModal calls onConfirm and then onDismiss (the list's hideCancelModal clears the selected reason, but the request has already captured remark).
- Logistics retry only retries the order info, not the logistics data (source behavior); a failed logistics request leaves the section showing defaults (`未知快递`, empty list).
- 售后/退款 tab = status [5,6], while the detail page title for status 4 is `交易完成` but the tab is `已完成`: two string sets coexist, and the closure check depends on these literals.
