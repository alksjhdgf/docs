## Data and APIs
- Address (core/model/.../entity/Address.kt): id, userId, contact, phone, province, city, district, address, isDefault (@EncodeDefault ALWAYS), createTime, updateTime.
- AddressService: POST user/address/page (PageRequest{page,size=10,sort="desc"}) → NetworkPageData<Address>; POST user/address/add (Address) → Id; POST user/address/update (Address) → Unit; POST user/address/delete (Ids{ids:[Long]}); GET user/address/info?id=; also user/address/list, GET user/address/default (used by order confirmation).
- CouponService: POST market/coupon/user/page (PageRequest) → page<Coupon>; POST market/coupon/user/receive ({couponId}) → String (message toasted); POST market/coupon/user/list.
- Coupon: id,title,description,type,amount(Double),num,receivedNum,startTime,endTime("yyyy-MM-dd..." parsed by date),status,condition{fullAmount} (custom serializer: the server may return a JSON string or an object),createTime,updateTime,useStatus(0 unused/1 used/2 expired, only in the "my coupons" API).
- FeedbackService: POST app/feedback/page (PageRequest) → page<Feedback>; POST app/feedback/submit (FeedbackSubmitRequest{contact,type:Int,content,images:List<String>?}) → Boolean.
- Feedback: id,userId,contact,type,content,images?,status(1=processed),handlerId,remark (customer service reply),createTime,updateTime.
- Dictionary: POST dict/info/data {types:["feedbackType"]} → DictDataResponse.feedbackType: List<DictItem{typeId,parentId,name,id,value:Int}>.
- Upload: POST base/comm/upload → OssUpload{url, credentials{tmpSecretId,tmpSecretKey,sessionToken}}; then for each image, a multipart POST to url with fields key=app/base/<uuid>_image.<ext>, tmpSecretId, tmpSecretKey, sessionToken, file; resulting URL = "$url/app/base/<file>"; any single failure aborts the whole batch (core/network/.../service/impl/FileUploadServiceImpl.kt).
- Local DB (Room): table footprints {goodsId PK, goodsName, goodsSubTitle?, goodsMainPic, goodsPrice Int, goodsSold Int, viewTime Long}; DAO: insert REPLACE, delete by goodsId, clear all, getAll ORDER BY viewTime DESC (Flow), count (Flow), recent LIMIT n, get by id.
- Navigation results: RefreshResultKey(RefreshResult{refresh}) for AddressDetail→AddressList and FeedbackSubmit→FeedbackList; SelectAddressResultKey(Address, JSON-serialized) for AddressList→OrderConfirm.
- Logout: AppState.logout() (core/data/.../state/AppState.kt:146) clears authStore and userInfoStore (MMKV) and resets isLoggedIn/auth/userInfo/userId.

## Cross-cutting notes
List pages (AddressList/Coupon/FeedbackList) share BaseNetWorkListViewModel: pageSize 10, first-load Loading→(minimum 320ms skeleton when enableMinLoadingTime)→Success/Empty/Error; a failure with an existing list only marks load-more as Error (`加载失败，点击重试`); refresh resets to page 1; with no next page it shows `没有更多了`. Detail-form pages (AddressDetail/FeedbackSubmit) use BaseNetWorkViewModel Loading/Success/Error, and the bottom button only appears in Success. The Footprint page has no network: it is driven by a Room Flow, so it updates automatically after clearing. Profile reads the global AppState user info Flow. Strings unused in source (`我的足迹` footprint_empty `还没有浏览记录哦`/`去逛逛`, `地址管理`, `默认地址`, etc.) should not count as required closure literals. In the feedback form, `isFormValid` is a function call recomputed on each recomposition. Every page has light/dark previews and follows the global theme.

## Platform risks
- Image picking: Android PickVisualMedia (single pick, no storage permission) → HarmonyOS should use PhotoViewPicker (photoAccessHelper, maxSelectNumber=1 or remaining count); the returned URI is file://media/..., and reading bytes needs fs.openSync before building a multipart body (http.request multipart or request.uploadFile/a hand-built boundary). Upload goes directly to Tencent COS with the temporary credentials in form fields, and the MIME type comes from the URI's extension.
- Room footprint table → HarmonyOS relationalStore (RDB) or preferences; Flow reactivity needs manual refresh notifications (clearing/revisiting must refresh the list and `清空 (%d)` count; the Me page's 8 recent items too).
- Region picker is ModalBottomSheet → bindSheet / CustomDialog; region data is a 535-line static Kotlin object that must be ported as-is (only 13 provinces; do not substitute a full national dataset, to stay behavior-faithful).
- Coupon expiry is judged on device with SimpleDateFormat("yyyy-MM-dd") against the current time; the condition field can be a JSON string or an object, so ArkTS must parse both shapes.
- isDefault must always be serialized (EncodeDefault); in ArkTS make sure false is not dropped by JSON.stringify/the optional-field strategy.
- Navigation results (popBackStackWithResult) → Navigation NavPathStack pop(result)/onPop callback, which must cover three kinds of returns: address selection, address refresh, and feedback refresh.
- Profile's avatar shared-element transition with the Me page (sharedElement "user_avatar") → geometryTransition, optional visual polish.
- Profile's avatar/nickname editing and coupon claiming are not implemented on these pages in the source (claiming lives in Home/GoodsDetail); do not invent these features.
