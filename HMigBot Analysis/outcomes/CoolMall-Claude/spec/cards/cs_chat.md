Note: markMessagesAsRead is called in createSession onData at the same time as loadHistoryMessages, when _messages is usually still empty, so it effectively may not send a request (behavior-faithful point).
- Unused in this module: `GET cs/session/detail`, `GET cs/msg/unreadCount` (CustomerServiceService.kt:26,55)
- CsMsg{id:Long,userId,sessionId,content{type:String,data:String},type:Int(0 user/1 agent),status:Int(0 unread),nickName,avatarUrl,adminUserName,adminUserHeadImg,createTime:String?,updateTime} (core/model/src/main/java/com/joker/coolmall/core/model/entity/CsMsg.kt:22)
- WebSocket: `wss://mall.dusksnow.top/socket.io/?EIO=4&transport=websocket` (hardcoded, not BASE_URL); hand-written Socket.IO frames: handshake `0{...}`, namespace auth `40/cs,{"isAdmin":false,"token":"<token>"}`, heartbeat server `2`→client `3`, push `42["msg",{}]`/`42/cs,["msg",{}]`, connection notice `42/cs,["message","连接成功"]`, send `42/cs,["send",{"sessionId":N,"content":{"type":"text","data":"..."}}]` (the content is concatenated directly into the string without JSON escaping). The token comes from appState.auth.token (ChatViewModel.kt:288).
- Sound resources: feature/cs/src/main/res/raw/send.mp3, receive.mp3; SoundPool maxStreams=2, USAGE_NOTIFICATION.
- No local persistent storage keys.

## Cross-cutting notes
State machine: uiState Loading→(createSession+page 1 success, after at least 320 ms) Success / Error; connection state Disconnected→Connecting→Connected / Error(msg), and the UI does not display connection state (_connectionState is used only internally). Reconnect: onFailure with retryCount<3 calls retryConnection, which only delays 1000*n ms and **does not actually reconnect** (the comment says the outside must call connect again); a real reconnect only happens when sendMessage finds it disconnected/failed and calls connectWebSocket. connect ignores a repeat call while Connecting. OkHttp's built-in ping is disabled (pingInterval 0), readTimeout is 60s, and the heartbeat relies on the server's 2/3. loadMore is triggered by snapshotFlow watching that the last visible item (the LoadMore item at the visual top) is visible and state==PullToLoad; ViewModel state pageSize=10, currentPage rolls back on failure. A new message emits newMessageEvent → after a 50 ms delay, animate the scroll to index 0.

## Platform risks
- HarmonyOS has no OkHttp: use @ohos.net.webSocket to hand-write the Socket.IO v4 frame protocol (same as the source, no socket.io client library needed); you must implement replying 3 to the heartbeat 2 yourself and the 40/cs namespace auth, otherwise the server disconnects after pingTimeout.
- The send frame is concatenated directly (no escaping): faithful migration keeps the same behavior, but it is recommended to use JSON.stringify to avoid breaking the frame when there are quotes/newlines (needs a ledger decision).
- Reverse list: ArkTS List has no reverseLayout; use List + initialIndex/scrollToIndex or a reverse-ordered data source + stack direction to get "newest at the bottom, load more on scroll to top" and the back-to-bottom threshold.
- Keyboard avoidance: HarmonyOS needs expandSafeArea / setKeyboardAvoidMode (RESIZE) so the input area rises with the keyboard; the emoji/function panels are mutually exclusive with the keyboard.
- Sound: replace SoundPool with @ohos.multimedia.media SoundPool (createSoundPool, usage notification/STREAM_USAGE_NOTIFICATION); copy the mp3 into rawfile; it can only be verified on a device.
- Emoji: some emoji (🫐🫑🫒🫔🫕🫖🪃🪂, etc.) may render as missing glyphs with the HarmonyOS system font.
- Gallery/Camera is unimplemented in the source (TODO); during migration it only collapses the panel and must not add image picking/upload by itself.
- Disconnect on leaving the page: tie it to the page/ViewModel lifecycle (aboutToDisappear), otherwise the connection leaks.
